GPU sorting in WebGPU

Two parallel sorts and the prefix sum under them, written in WGSL compute shaders and running on your GPU in this page: an LSD radix sort built on prefix sums and a bitonic sorting network. Each is checked against the browser's own sort. The same algorithms are ported to CUDA in the repository, so the numbers can be compared across APIs.

This browser doesn't support WebGPU, so the demos can't run here. Recent Chrome, Edge, Safari and Firefox all support it.

Watch it sort a picture

The picture is 262,144 pixels, and each pixel's key is the place it belongs. The page shuffles them, sorts the keys on your GPU and reads the array back after every pass. The array is drawn row by row, so sorted runs of keys show up as small, rough copies of the picture. Bitonic doubles the size of those copies at every stage until one is left, and every other run is upside down because it sorts alternate runs in opposite directions. Radix sorts the lowest digits first, so nothing shows until the last passes.

Prefix sum

An exclusive scan over 32-bit values. Each 256-element block is scanned in workgroup memory, the block totals are scanned the same way one level up, and a second sweep adds them back down. Three levels cover 16 million values. The radix sort calls it once per pass to turn digit counts into output offsets.

Radix sort

Four bits per pass, eight passes for 32-bit keys. Each pass counts digits per 1,024-key tile, runs a multi-level exclusive prefix sum over the counts, then scatters. The scatter ranks keys inside a tile with a workgroup scan over sixteen packed 16-bit counters, so the sort stays stable without atomics on the output.

Bitonic sort

A sorting network with O(n log² n) compares. Steps that stay within a 512-key tile run in workgroup memory in one dispatch. Longer strides go to global memory, one dispatch per step. It does more work than radix but every step is the same shape, which makes it a useful baseline.

CUDA port

The repository has the same two sorts and the prefix sum in CUDA, with the same tile sizes and digit width, benchmarked against the CPU and CUB's radix sort and scan. On an RTX 2080 Ti it sorts 16.7 million keys in 16.3 ms with radix and 30.0 ms with bitonic, almost exactly what the WebGPU versions take. CUB's radix sort does it in 1.66 ms.
